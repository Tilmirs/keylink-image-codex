# Keylink Image

This is a standalone Codex skill. Resolve paths relative to the directory containing this `SKILL.md`. Use the bundled client at `scripts/keylink_image.py` with Python 3.11 or newer. On Windows, `scripts/keylink-image.ps1` resolves the Python runtime automatically. On macOS/Linux, use `sh scripts/keylink-image.sh`; it checks the skill's `.venv`, PATH, and Homebrew locations, or accepts an explicit `KEYLINK_PYTHON` interpreter. Keep API keys out of command-line arguments and output.

## Decide the operation

1. Treat an explicitly uploaded image as the reference image, even when a previous result exists.
2. When the user says the result is unsatisfactory, visually wrong, or asks to change the image just produced, edit the latest successful image for this Codex task. Pass only the requested changes as `--prompt` and add `--use-last`.
3. When it is unclear whether the user wants a new image or an edit, ask which operation they intend. After they choose editing, reuse the latest image without asking them to upload it again.
4. Pass explicit uploads with one `--image <path>` per image. Uploaded images take priority over `--use-last` inside the client. Use the default `--mode auto` with references, including when the user asks to create a new composition from them. References always select image editing, even if `--mode generate` is accidentally supplied. For an explicitly independent new image, omit `--image` and `--use-last`; use `--mode generate` to prevent implicit reuse of the last image.
5. Preserve the user's model ID exactly. Model IDs are pass-through values, including `gpt-image-2.5`, `gpt-image-2.5-sunburst`, and `gpt-image-2.5-flare`. Treat variants as separate catalog choices; never strip their suffixes or substitute the base model during generation, editing, or fallback.

For an edit that should keep its canvas, omit `--size` and `--aspect`: the client inherits the original reference's pixel dimensions, after EXIF orientation and before upload compression. Explicit size/aspect options override this, so do not supply `--aspect square` as a default for edits. If reference dimensions differ or cannot be read, ask the user for the output size. Inheriting a nonstandard/high-resolution size still requires size confirmation; never silently reduce it to 1K. Keep the same resolved size through endpoint fallback and detached workers.

When the user asks to increase resolution (for example, to 4K), pass the confirmed target as an explicit `--size`; inheriting a smaller reference canvas does not fulfill that request.

For edits, use only the current requested changes, required on-image text, and preservation constraints. Exclude chat history, system/tool instructions, logs, command examples, and embedded Base64. Apply the user's prompt mode below: restrained text must remain exact; creative/master edits refine only the requested changes, without redesigning preserved content. The legacy client can unwrap explicit transcript/JSON/context wrappers; explicit prompt modes reject wrappers instead of silently changing the final text. If restrained input is ambiguous, wrapped, or overlong, ask for a clean/shorter visual prompt rather than rewriting it. Do not truncate any prompt to fit.

The client inspects reference image bytes and dimensions before sending either endpoint. Accept at most 15 references, each at most 1 MiB after preparation; they do not share a 1 MiB budget. Preserve compliant smaller files byte-for-byte. A lower server-published total budget may require further compression, starting with the largest uploads. Excess image counts stop before submission; ask the user to choose fewer images instead of silently dropping any. The client creates upload copies when needed and snapshots all references for detached jobs. Pass original uploaded/saved image paths; never substitute display previews. Pillow is required for resizing, compression, orientation correction, or unsupported input formats. If unavailable and a reference needs conversion, install it into the launcher's Python environment before retrying. Explain normalization using `reference_images` and warnings; requested output pixels stay unchanged. Read [references/routing.md](references/routing.md) for client budgets and published input limits.

## Choose model, count, design brief, and prompt mode

- At the start of each new generation/edit request, run `models` once using the execution guidance below. It calls `GET /v1/models`, saves a one-use selection token for the current Codex task, and reports server-published sizes. Waiting for the user's choices, receiving their reply, completing the brief, or resuming the same unsubmitted request is not a new request: retain this catalog and unused token across turns. Do not refresh just to obtain a token again. Refresh only for a genuinely new request, a user-requested refresh, or a missing/replaced/consumed/wrong-host selection; an existing job requires `status` first. A refresh requires a choice from the newly returned catalog.
- Show the returned `image_models`. In the same interaction, collect model, output count (1–4, default 1), prompt mode, and any content/style preferences the user wants to provide. The subject can come from their earlier message; optional design details are not a required form. **Display all three mode names with their explanations in the user-facing question**, even when a question tool is used. The JSON descriptions alone do not count as displaying them. Keep model selection independent of mode; do not create model/mode packages or omit restrained mode:

  | Choice | Meaning | Client flag |
  | --- | --- | --- |
  | 克制模式 | 原文原样发送，不补词、不改风格或构图；适合已有完整提示词 | `--prompt-mode restrained` |
  | 创意模式 | 保留原文主体，只补充 1～3 处必要的构图、配色或光线细节；适合轻度润色 | `--prompt-mode creative` |
  | 大师模式 | 保留目标、指定文字与限制，重写为完整设计方案，统筹视觉概念、布局和文字层级；适合让 AI 主导设计 | `--prompt-mode master` |

  Use an available question tool with separate questions or one free-text reply: the question itself must include the three descriptions above and the actual model list. Offer: "可回复：模型名，1 张，大师模式。内容沿用你刚才的描述；风格等可选填，创意／大师模式会按各自程度补齐。" Carry forward details already supplied instead of asking again. A model-only reply accepts the stated count default if omitted; it does not select a prompt mode. More than 4 outputs requires a choice of 1–4; never clamp or split into additional batches. Wait for the user's model choice from this catalog and mode choice; if only these essential choices are missing, ask only for them. Keep a mode explicitly retained across requests until changed.
- Once subject, model and mode are known, complete missing optional design details according to the mode and execute; do not send another style/use/layout questionnaire. Creative makes a small refinement, master develops a coherent design, and restrained adds nothing to the prompt. Select a conservative aspect appropriate to a clear deliverable (for example portrait for a poster, landscape for a banner), or square when unclear; preserve edit dimensions and explicit size choices. Briefly state inferred direction as a progress update without requiring routine approval. Ask only when the subject itself is unknown, an essential fact or exact requested text is unavailable, requirements conflict, reference roles/edit intent are unclear, or resolution requires confirmation. Do not invent commercial facts, identities, prices, dates or measurements.
- For creative/master, read [references/prompting.md](references/prompting.md), then only the relevant category in [references/design-recipes.md](references/design-recipes.md). Apply its mode-specific checks before sending; a different label alone is not a different mode. Codex prepares the final text; no extra text-model API request is needed. Restrained mode sends the user's visual prompt byte-for-byte, including language, punctuation and whitespace. Keep separately supplied style notes out of restrained text unless incorporated by the user. Do not add a template, negative prompt, automatic word replacement or inferred design details to restrained text.
- For master requests allowing full design, apply the concept-to-layout workflow in prompting.md and the scenario/style table in design-recipes.md. Posters and covers prioritize flat graphic composition, deliberate typography, grid alignment, negative space, and theme-derived supporting elements with clear functions. Choose one coherent direction; do not default to 3D mockups or generic decorative clutter. Photography, text-free artwork, and limited edits retain their own scope.
- Pass the chosen model unchanged with `--model`, count with `--count`, mode with `--prompt-mode`, the final visual prompt with `--prompt`, and the token with `--selection-token`. The client rejects missing, stale, reused, wrong-task, wrong-host, and unlisted model selections. A new generation or edit requires a fresh `models` call and a fresh user model choice. Once the prompt and required choices are available, optimize as authorized and submit without an additional routine prompt-approval step; ambiguity and high-resolution confirmation still follow the existing rules.
- Correcting the same request after input preflight fails (for example, an invalid reference path or rejected edit prompt) is not a new generation. If no job has started and the selection token is still unused and current, keep the chosen model, count, token, and confirmed size, fix the input, and retry without calling `models` or asking for the same model again. For an existing job, check `status`; never reset or bypass a consumed/replaced token.
- Prefer `1024x1024`, `1536x1024`, or `1024x1536` for `gpt-image-2`, the `gpt-image-2.5` family (including `sunburst` and `flare`), and supported Gemini image models. Choose among them from the requested aspect ratio. Read sizes for the exact selected model ID; do not inherit published sizes from its base model or another variant. Do not assume `2048x2048` when the catalog does not publish it.
- `gemini-nano-banana-2.1` is a recognized Gemini image model even when its catalog entry has no image capability metadata. Offer it only when the current catalog returns that exact ID; preserve it in generation, reference edits, and continued edits. Use Images first, then Chat, with the same size rules as other Gemini image models; an explicitly selected endpoint stays fixed.
- Treat "更高分辨率", "高分辨率", "高清", "超高清", "2K", "4K", "UHD", or an explicitly larger pixel size as high-resolution intent. Show the published sizes plus relevant experimental candidates such as `2560x1440` and `3840x2160`, then wait for user confirmation before running the image request.
- Before starting a confirmed `2560x1440` or `3840x2160` request, tell the user that high-resolution generation can take several minutes and ask them to wait patiently. Use the detached `start` command for these sizes, then poll `status` with the returned job ID. The detached worker receives and saves the response after this Codex turn is interrupted; never submit a second request while the job is running.
- After confirmation, pass `--confirm-high-res`. Never locally upscale, silently downgrade to 1K, or change the model. A Chat success may not honor the requested pixels; state that limitation and report detected dimensions when available.
- Use `--endpoint auto` unless the user explicitly fixes `images`, `chat`, or a custom endpoint. Explicit endpoint choices never fall back.
- For custom endpoints, pass `--endpoint custom --custom-url <url> --custom-kind chat|images`.

Output count is separate from reference-image count. Images Generations/Edits send the chosen count as `n`; Chat requests one output at a time, up to that count, with the same prompt, model, size, and input references. Keep quantity instructions out of the creative prompt: do not ask for a collage to simulate multiple files. Use detached `start` for multiple outputs as well as high-resolution requests. Tell the user that several images can take longer. All outputs belong to one selection token and one job; never repeat `start` while it is running. If the user later asks to edit an unspecified image from a multi-image result, ask which output they mean, then pass its original path with `--image`.

Read [references/routing.md](references/routing.md) when endpoint order, multi-image handling, high-resolution handling, or response compatibility affects the request. For creative/master social content (小红书、抖音、视频号、公众号、B 站、知乎 covers, post illustrations, tutorial cards or video inserts), read [references/social-media.md](references/social-media.md) for the platform/deliverable guidance. Restrained mode does not add those design templates. Prompt optimization must not add unconfirmed resolution instructions, change model/count/reference roles, or change Images → Chat routing.

## Run the client

Use JSON output to determine the saved image path and warnings:

```powershell
& "<skill-dir>\scripts\keylink-image.ps1" models
& "<skill-dir>\scripts\keylink-image.ps1" run --prompt "<final-visual-prompt>" --prompt-mode master --model "gpt-image-2" --count 1 --selection-token "<token-from-models>" --aspect landscape --endpoint auto
& "<skill-dir>\scripts\keylink-image.ps1" run --prompt "change only the sky to sunset" --prompt-mode restrained --count 1 --model "gpt-image-2" --selection-token "<fresh-token>" --use-last
& "<skill-dir>\scripts\keylink-image.ps1" run --prompt "<final-visual-prompt>" --prompt-mode creative --count 1 --model "gemini-3.1-flash-image" --selection-token "<fresh-token>" --image "C:\path\reference.png"
& "<skill-dir>\scripts\keylink-image.ps1" start --prompt-file "<final-prompt-utf8.txt>" --prompt-mode master --count 1 --model "gpt-image-2.5" --selection-token "<fresh-token>" --size "3840x2160" --confirm-high-res
& "<skill-dir>\scripts\keylink-image.ps1" status --thread-id "<thread-id>" --job-id "<job-id-from-start>"
```

For multiple outputs, use `start ... --count 4` (or 2/3), then query the returned job with `status`.

For exact text, multiline prompts, quotes or shell metacharacters, write the final visual text to a local UTF-8 file using file tools (such as `apply_patch`), then run a separate command with `--prompt-file <path>` instead of `--prompt`. Do not interpolate visual text into shell code or nest it inside PowerShell `-Command`; a PowerShell here-string needs a newline after its opening marker and its closing marker on its own line. After a shell parse failure, correct file creation without refreshing the model selection or claiming submission. The file reader ignores an optional UTF-8 BOM encoding signature and preserves content, whitespace and CRLF/LF; background jobs snapshot the text, so workers do not depend on that file. These mode values in examples illustrate choices; always use the user's actual mode.

Send model discovery, generation, and editing requests directly to `https://keylinkclub.com`. Do not route them through Codex or CCSwitch's local API listener. The only address overrides are an explicit `--base-url` or `KEYLINK_BASE_URL`; generic `OPENAI_BASE_URL` and `OPENAI_API_BASE` are ignored. HTTP/SOCKS network proxies are separate from the API base URL; do not use their listening port as `--base-url`.

Read credentials without printing them. An explicitly configured `KEYLINK_API_KEY` wins. Otherwise read the saved CCSwitch provider configuration, supporting the legacy current provider and the new routing/aggregation state. In aggregation, find a member of the saved enabled stack matching the API host; do not assume the default provider is Keylink. A saved matching key remains usable when CCSwitch is closed or its running state cannot be checked because requests go directly to Keylink. This does not prove CCSwitch is running. If several matching members have different keys and none is the default, ask the user to select the intended Keylink default or configure `KEYLINK_API_KEY`. Legacy local-only provider addresses still require a confirmed running instance; do not use an unverified saved key for an unrelated host.

Before `models`, inspect the current tool/environment permissions. If they explicitly restrict the required network access, and an approved host-execution facility is available and permitted, request it for the first read-only catalog call (Codex `exec_command`: `sandbox_permissions: require_escalated`, with a reason such as "查询 Keylink 可用图片模型需要网络访问"). Do not deliberately make a known-blocked request first. Otherwise use normal execution. After approval, reuse the execution route within its actual permitted scope; never infer cross-task approval, disable the sandbox, alter proxy/security settings, or let the script self-elevate. When escalation is forbidden or unavailable, obey that restriction.

If a normal catalog call fails with a concrete access-denied socket error such as WinError 10013/EACCES and a permitted host retry is available, request at most one retry of the same GET. This error indicates an access restriction, not by itself proof that the sandbox rather than a firewall caused it. HTTP 401/403, DNS, timeout and connection-refused errors are not evidence of sandbox denial. Describe the observed error accurately; do not print a routine "sandbox blocked" message before every query. Any real permission request must still state its reason; if denied or unavailable, report the limitation instead of repeatedly retrying.

If the client returns `ccswitch_detection_required` / `requires_host_execution`, no usable saved key matched the API host and processes or the local listener could not be checked; `ccswitch_running: null` means unknown, not stopped. Use the same permitted host-execution flow once, only if the command was not already running there. Do not infer a running process from saved files, ask the user to replace keys, or retry with `--confirm-codex-auth`. If host execution remains unavailable or detection still fails, explain the restriction and give the same command for the user's own terminal. This read-only retry rule does not authorize resubmitting an image job: inspect its result/status first.

When CCSwitch cannot supply a key and its running state is known, check Codex/Codex++ login status before any fallback. If an account login is present, return an error and ask the user to configure and save a real Keylink key in CCSwitch (add Keylink to aggregation when applicable) or `KEYLINK_API_KEY`. Do not use account `auth.json`, account tokens, or generic `OPENAI_API_KEY`; `--confirm-codex-auth` does not bypass this rule. Do not overwrite the user's account login.

Only when no account login is detected may API-key-only `auth.json`/config files or `OPENAI_API_KEY` serve as fallback, including when CCSwitch is running but has no usable key. On `credential_confirmation_required`, ask whether the candidate is a Keylink API key, then retry with `--confirm-codex-auth` only after confirmation. `PROXY_MANAGED` is a local routing placeholder and must never be sent as a Keylink key. See [references/routing.md](references/routing.md) for compatibility details. A macOS app opened from Finder may not inherit terminal exports.

The client uses Python's system/environment HTTP proxy support, including `HTTPS_PROXY`, `HTTP_PROXY`, and `NO_PROXY`. For a VPN, use its HTTP/mixed port or system tunnel; a SOCKS-only URL is not supported by this transport. Do not change the API host to address a network proxy issue.

The latest successful image is stored under `.keylink-image/threads/<thread-id>/` in the current workspace. The client uses `CODEX_THREAD_ID` or `CODEX_SESSION_ID` automatically and records the latest image only after it is saved successfully. Detached jobs are stored under `.keylink-image/threads/<thread-id>/jobs/<job-id>/`; they keep the same workspace and resolve credentials when the worker sends the request.

## Return the result

- Include the chosen mode and the exact `sent_prompt` in a copyable text block with the images. Label restrained text "实际使用的提示词（原文，未改写）" and creative/master text "优化后实际使用的提示词". Use the saved field from `run`, completed `status`, or `last`, not a newly reconstructed version. A started job's `prepared_prompt` is prepared input, not proof of submission or success. Older results without `sent_prompt` cannot be reconstructed reliably; state that it was not recorded. For API failures, report the failure and recorded sent prompt without claiming an image exists.
- Report `returned_count` against `requested_count` and display every saved image. `count_complete: false` means only part of the requested count was saved, even when `status` is `ok`. Do not call the whole batch complete. Preserve those files; do not automatically top up, switch endpoints, or reuse the token after any image has been saved. A later refusal stops the remaining calls; report the refusal and return only the images already saved before it.
- Display each image using the returned `display_markdown` and include its `original_markdown` link. Paths use forward slashes and angle brackets for Windows/space compatibility.
- Large images get a separate JPEG display preview when Pillow is available. This preview is only for inspection/display; the original file and its actual dimensions remain the deliverable and the reference for subsequent edits. Never pass the preview as the next reference image.
- If `view_image` fails with `invalid base64`, `Invalid padding`, or an oversized payload, use `display_path`. A preview error does not mean generation failed; still return the saved original link, without sending a new image request.
- Include the model, endpoint actually used, requested size, and detected pixel size when available.
- Check each image's `matches_requested_size`. If false, explain that the provider returned different pixel dimensions and deliver the saved original with its actual dimensions; do not label it as matching the request, resize it locally, or automatically submit another generation. Upload compression alone does not determine the requested output pixels; inspect `size_source`, `reference_images`, and `requested_size` separately.
- Wait for the actual command/session result before declaring success. Before invoking `run`/`start`, describe input preparation or the next submission, not "request submitted"; file creation and shell parse failures are not submissions. A tool call returning a running session is not a completed generation. Only return images from this request's successful `run` result or matching completed job; a content refusal or API failure must be reported as failure, never replaced with an input image or an earlier successful result.
- `provider_refused: true` means the provider explicitly blocked a request. If `returned_count` is 0, report that no new image was generated. If earlier calls in this batch saved images, report the partial count and that the remaining request was refused; do not automatically switch endpoints/models or rewrite the prompt to evade that refusal.
- If both automatic endpoints fail, summarize both errors and ask whether to switch models. Do not switch models before the user agrees.
- Distinguish HTTP/API errors (including 400/413), connection failures, a successful response without an image, and a returned image that failed to download/decode. Inspect `attempts`, `request_attempts`, and `prompt_info`; do not describe an HTTP/API rejection as a missing image link. A client upload budget reduces oversized requests but cannot guarantee acceptance by an undocumented channel limit.
- If the user explicitly fixed an endpoint, report that endpoint's failure without trying another one.

## Recover a missing display

When the user reports success without an image, or resumes an interrupted generation, check `status --thread-id <thread-id>` first when a background job may exist. It reads the detached worker's local result and never submits a new request. Use `last` in the original workspace afterward for a completed saved result or for a request made by an older client. Compare `saved_at`, `request_id`, and job timestamps with the request time so an older result is not mistaken for a still-running request. If the generation session is still active, poll that same session for its final result.

`last` rejects a previous image when a newer request has no saved successful result, including failed/refused or still-running requests. Do not bypass that rejection to claim success. Only use `last --allow-previous` when the user explicitly wants an earlier saved image; `historical: true` and `current_request_succeeded: false` must be described as a historical result. This does not change which saved image `--use-last` uses for an explicitly requested edit.

The default `status` also rejects an old background job when a later request exists. An explicitly selected old `--job-id` remains inspectable and is marked `historical`; it must not be presented as the later request's result. If a successful request reports `state_recorded: false`, its image files were saved but the local history update failed: return those exact paths and the warning, without submitting another generation.

For a detached job, run `status --job-id <job-id> --thread-id <thread-id>` first. A `running` response means the request already exists and must not be resubmitted. A successful status response contains the saved image; use its `display_markdown` and `original_markdown`. Only run `last` after the status is complete or when the task predates detached jobs.

```powershell
& "<skill-dir>\scripts\keylink-image.ps1" last --thread-id "<original-task-id>"
```

Use `--preview-dir <writable-directory>` when recovering from a workspace that cannot be written. Pillow is optional for generation; it is needed to create display previews. If unavailable, return the original image link and explain the preview limitation.

On macOS/Linux, recovery uses `sh "<skill-dir>/scripts/keylink-image.sh" last --thread-id "<original-task-id>"`. To enable previews without modifying system Python, create a Python 3.11+ virtual environment at `<skill-dir>/.venv` and install Pillow into it; the shell launcher discovers it automatically.
