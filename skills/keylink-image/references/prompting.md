# 提示词模式与优化流程

在用户选择大师模式或专业模式时读取；具体设计方向见 [design-recipes.md](design-recipes.md)。这些规则由 Codex 执行，不是 Python 的自动改写器，也不额外调用付费文本模型。

## 按具体度决定优化幅度

先区分用户已经给足视觉信息，还是仍留下关键方向待定。详细提示词只整理成清楚、可执行的规格，不增加创意要求；笼统提示词才适度补充，且每项补充都必须能实质改善结果。优先考虑构图/取景、实际用途、实用排版或支持主题的具体场景；不添加原意未暗示的人物、道具、品牌色、口号或故事，也不做没有依据的左右位置决定。

复杂任务可以按“场景/背景 → 主体 → 关键细节 → 限制 → 用途”组织成短行；简单任务用一至三句自然语言。结构只是整理工具，不是字段表。背景、光线、材质、文字层级和辅助元素都属于可选决策，只在原需求、所选参考图或交付目的使其有用时纳入。

## 先收集，再按模式处理

模型查询完成后，同一步收集本次目录里的模型、输出数量与模式，附带邀请用户填写内容/用途、风格；已有信息直接沿用，可选项不用填满。必须在同一条用户可见的提问里展示三种模式及下表说明，只展示一次，不把某个模式绑定某个模型。用户回复选项仍属于同一未提交请求，复用已有目录与未消耗的 token，不因为进入新一轮对话就再查目录。

用户已给出主题后，只回复“模型名，1 张，专业模式”就足够继续：专业模式先按主题检索风格参考供用户选择，大师模式负责整体设计。数量省略按已展示的默认 1 张；模型或模式未选且未明确授权代选时仅补问该选择。只有整个请求都没有主题时才问想画什么，不让用户再次输入已有提示词。

缺省画幅根据明确交付物选择保守尺寸，例如海报竖版、横幅横版，无明显方向则方图；编辑沿用原始底图尺寸。文字和新增内容遵循用户授权：不把参考图上的文案搬进来，也不凭空补品牌或事实；当用户明确要完整广告/海报创意时，可拟简短、非事实性文案，否则只安排已提供的文字。缺失的品牌、日期、价格、功效、身份、业务数据等事实不能编造，能省略就省略，必需时只问这个缺项。高分辨率、混合参考尺寸、关键意图冲突仍走主 Skill 的确认流程。专业模式的参考图选择完成后直接进入生成，不增加固定风格问卷。

| 模式 | 处理边界 | 适用做法 |
| --- | --- | --- |
| 克制 restrained | 原文原样发送，适合已有完整提示词 | 不翻译、不润色、不增删、不替换词汇，保留空格、换行、引号；不补缺失的视觉细节。模式/模型/数量等另作参数。边界不明时先问哪段是原文。 |
| 大师 master | 围绕原目标重写，适合让 AI 主导设计 | 用户授权整体设计时，自主确定一个连贯方向，并补齐影响成品的关键决策；按题材选择构图、层级、环境、光线或辅助元素，不要求每张图都包含所有维度。 |
| 专业 professional | 先选参考图，再依据选择定向调优提示词，适合希望从视觉实例出发的人 | 仅在花瓣、搞定设计、Pinterest、Dribbble 检索，每批展示 10 张候选；支持模糊扩展检索、按序号选择或“换一批”。将用户素材和每张已选参考图按角色区分；仅提取与需求相关的构图、配色、背景、光线、材质或文字层级特征，不自动套用完整大师方案。 |

模式名不代表固定视觉风格。“克制模式”不是极简风，“大师模式”也不默认黑金、奢华、电影风或超模。用户明确的风格优先于模板。继续编辑时沿用用户明确保留的模式，否则补问；不要重新询问已提供的内容。

## 同一需求的三种处理与发送前检查

原文：`咖啡海报，标题“慢一点”，棕色系。`

- **克制**：`咖啡海报，标题“慢一点”，棕色系。` —— 必须逐字相同，不能悄悄增加“高级感”、负面词或副标题。
- **大师**：`设计一张咖啡主题海报，让标题“慢一点”与咖啡主体形成清晰主次，以棕色系为主；标题准确可读，不添加其他文字。` —— 对笼统需求选择一个方向，只补关键关系与限制，不扩写无关细节。
- **专业**：先检索“咖啡海报 复古平面排版”，用户选图后只提取它确实提供的方向，例如网格、字重或套色关系，再把这些要点融入原要求；如果原提示词已经完整，就只说明参考图承担的角色，不强行补齐背景、光线和辅助元素。—— 参考图先选择，提示词后定稿，不自动照搬原图内容。

示例说明处理幅度，不默认把所有咖啡海报做成这个布局。发送前按所选模式检查：

1. 克制：最终文本与用户视觉原文完全相同。脚本明确模式下拒绝包装内容不能成为擅自改写理由。
2. 大师：有一个可执行且自洽的视觉方案，体现布局与层级决策。仅改标题等局部编辑的方案必须限定在允许改动范围。
3. 专业：用户明确选择了参考图；最终提示词说明每张图的角色，以及实际借用的相关视觉特征。只在原需求或参考图使其有用时补充背景、构图、层级、光线、材质或辅助元素；不要求逐项覆盖，大师模式也不自动成为模板。网站图不覆盖用户素材的身份、产品结构、文字和禁用项。
4. 三种模式均保留精确文案、身份、产品事实、参考图作用、禁用项、模型/数量和已确认尺寸。不要通过删除这些约束制造“区别”。

返回时使用保存的 `sent_prompt`，大师/专业可用一句话说明重组了哪些设计要点；专业模式同时列出用户选择的参考图来源和用途，克制标注“原文未改写”。这是提示词处理方式的真实区别，不保证随机生成的图片一定达到某种审美等级。

## 不可改写的要求

- 原样保留标题、标点、姓名、品牌字样、UI 标签、数字、单位和用户指定的语言；用引号界定画面文字，不能把说明文字当作要印在图中的正文。
- 尊重用户设定的人物身份、外形、服饰、构图与禁用项。参考图逐张指定作用，例如“参考图 1 保留人物，图 2 仅取配色”；不合并、换序、丢图或把参考预览当原图。
- 编辑只优化本轮变化和必要保留条件。“只改标题”不能变成整张海报重设计。即使大师模式也不能重新描述整段会话、擅自换脸或重构不许变的布局。
- 数量、端点、模型和像素尺寸用客户端参数控制。不要为显得专业而加入 2K/4K/8K/UHD、未确认像素尺寸，或把四张独立输出写成四宫格。已确认的画幅可用构图语言表达，不能冲突。
- 实际内容无法满足时直接说明；不要靠同义词、语言切换或杂志标签隐藏不允许的意图。服务端明确拒绝后沿用停止规则，不自动改写重试。

要求冲突时先做一次针对性澄清，而不是替用户选边。例如“必须显示标题”同时“不要文字”，或“只改标题，其余不变”同时要求参考另一张图调色。克制模式保留原文不动；确认的是视觉意图，不是自动同意改写。多参考图仍遵循客户端的尺寸检查；不能仅因某图只参考风格就忽略它，尺寸混合时明确使用底图的输出尺寸并按需确认。

## 大师模式：从目标到设计方案

用于用户授权整体设计、希望 Codex 主导视觉决策的请求。大师模式负责选择并表达一个完整、连贯的方案；“完整”指成品意图明确，不代表提示词必须覆盖固定字段。局部编辑仍只在授权范围内应用。纯摄影、无字插画、商品白底图不强加标题、网格或装饰；样机和空间透视也只在交付物需要时出现。

1. **先判断成功条件**：抓住交付物、主体、使用场景和用户明确的文字/限制。细节充分时只整理为清楚规格，不另加创意要求。
2. **为未定方向作主**：需求笼统且用户授权设计时，选择一个最适合主题和用途的视觉概念。将抽象评价转成可见的设计关系；不输出多个备选方案，也不把“高级、精美、电影感”等形容词当成方案本身。
3. **只补关键视觉决定**：根据成品需要，选用主体尺度/视角、构图与焦点、标题层级、背景、光线/材质、留白或少量辅助元素。每项补充都应解决可读性、识别度、氛围或信息组织中的一个具体问题；没有帮助的维度省略。
4. **保留原意并收束**：精确文字逐字保留；不擅自新增文案、品牌、道具、人物、故事、配色限制或事实。用户已指定布局、风格或背景时沿用，不用重新设计覆盖。
5. **写成图像模型可执行的提示词**：简单需求用一至三句清楚描述；复杂信息才用少量短标签行。可按“场景 → 主体 → 关键细节 → 约束 → 用途”组织，只保留能帮助当前成品的部分，不填无关字段。
6. **检查是否过度补写**：逐项确认新增内容确实服务目标，指定内容、素材身份与保留范围准确；删除可有可无的道具、重复形容词和冗长负面词。

笼统输入示例：原文“咖啡海报，标题‘慢一点’，棕色系”。
> 设计一张咖啡主题海报，让咖啡主体与标题“慢一点”形成清楚的主次关系。以棕色系为主，标题准确可读，不添加其他文字。

具体输入示例：原文“竖版咖啡海报，米色背景，标题‘慢一点’用深棕色粗衬线字置于顶部，杯子在下半部，左侧柔光，复古套色纹理；只显示标题，不加标志”。
> 竖版咖啡海报：米色背景；深棕色粗衬线标题“慢一点”置于顶部，咖啡杯位于下半部，左侧柔光，复古套色纹理。只显示指定标题，不加标志。

第一个例子只为笼统请求补少量关键关系；第二个只整理原要求，没有加入创意细节。它们都不是咖啡海报模板。

## 组织方式

按**交付物 → 风格 → 使用场景**读取 [design-recipes.md](design-recipes.md) 中最相关的建议，不把配方当作默认模板。大师模式由 Codex 根据目标选择方向；专业模式由用户选定的参考图提供方向。先内部对照已明确要求和仍缺少的决定，最终提示词只保留相关视觉信息，不输出设计分析或完整检查清单。两种模式都不需要固定风格问卷；只有不同答案会改变主题、事实或关键约束时才澄清。

最终提示词可用以下要点检查，但不是填表：交付目的/主体、场景或背景、构图/焦点、真正需要的文字层级、影响氛围的光线/颜色/材质、关键限制。详细请求通常只需归整；笼统请求才从相关要点中补足少数关键决定。专业模式另明确每张所选参考图的角色和实际借鉴特征。写成自然、简洁的视觉描述，不输出设计分析、字段名或 JSON。

中文请求默认保持中文；除非用户要求，不翻译成英文来假设“效果更好”。摄影术语按需使用，镜头/光线应服务画面，不能承诺真实摄影器材或印刷级精度。

## 人物措辞与视觉质量

从 editorial-allure-prompting 借鉴正常的摄影/服装语言：用可见的姿态、表情、衣料、光源和空间关系描述想要的效果。词汇是表达工具，**不是违禁词替换表**；不承诺“100% 过审”，不把普通服装或身体词汇一律当作违规词。

| 模糊审美表达 | 按目标选用的具体化示例 |
| --- | --- |
| 高级、有气场 | 挺括羊毛外套的肩线、平视机位、稳定站姿、背景减少干扰 |
| 有电影感 | 明确主光方向、冷暖环境光关系、适度景深和统一色调 |
| 自然、不像 AI | 保留皮肤细节、自然表情、合理手势与真实环境反光；避免过度磨皮 |
| 有时装质感 | 写清剪裁、面料垂坠、接缝、配饰与衣料反光，而非叠加空泛形容词 |
| 生活感 | 手持视角、日常动作、自然曝光与适量环境细节，不强行套杂志摆拍 |

仅在语义合适且能改善目标时选用一两项具体化，不要把表格变成扩写清单。克制模式不做这些处理。人物风格不能自动改变年龄、体型、肤色或身份，也不能把普通日常人像升级成成人化或性化场景。

## 发送与返回

由 Codex 生成最终提示词，使用所选 `--prompt-mode` 与最终 `--prompt` 调用 `run`/`start`。有精确文案、引号、多行或 shell 特殊字符时，用文件工具将最终文本写入本地 UTF-8 文件，改用 `--prompt-file <path>`，防止命令行转义改变文字或执行文本。客户端只发送该文本，不再做语义优化。明确模式的编辑输入若仍含会话包装会在本地拒绝；克制模式请用户提供干净的原文，大师/专业模式只整理当前视觉要求。旧命令不带模式时仍兼容原来的编辑包装清理。

发送前核对题材、指定文字、参考图作用、保留项、画幅和用户选择。无需常规增加一轮“确认优化稿”；按已选模式处理并执行。高分辨率与真正歧义仍需按主 Skill 处理。

返回图像、实际数量、模型与尺寸，并逐字附上结果 JSON 的 `sent_prompt`。后台 `status` 与 `last` 也保存/返回这个字段；不要再次优化后冒充实际发送稿。克制模式标注“原文，未改写”，大师/专业模式标注“优化后实际使用的提示词”；专业模式另外列出用户选择的参考图 URL 和用途。只有 `prepared_prompt` 的任务刚启动，不能宣称请求成功。旧记录缺失时明确说明未记录。

来源与许可见 [sources.md](sources.md)。上游是设计参考，不控制本 Skill 的端点、授权、账号配置和重试行为。
